# alivio

A user-space mirror of the Linux kernel BPF verifier, written in Rust. Alivio
verifies the safety of BPF bytecode by reconstructing control flow graphs,
tracking register values with abstract interpretation (Difference Bound
Matrices and Tri-state Numbers), and validating memory accesses, context
usage, and map operations. On top of the mirror it generates **BCF proof
bundles**: machine-checkable SMT proofs that a BCF-patched kernel uses to
discharge verifier rejections at load time.

**Status:**

* **BCF milestone:** 360/360 real-world BPF objects (calico 337, cilium 17,
  bcc ksnoop 3, Inspektor Gadget 3) load on the BCF-patched kernel with
  fully-discharged proof bundles generated by `alivio --bcf --kernel-mode`.
* **Selftest baseline:** 3267+ PASS with 0 false accepts against the Linux
  kernel BPF selftest corpus (see [CHANGES_v6.15.md](CHANGES_v6.15.md) for
  the v6.15 feature list).

## Quick start

Verification alone needs nothing but Rust — no kernel, no solver:

```bash
cargo build --release
./target/release/alivio verify bcf-tests/shift_constraint.bpf.o
```

That object contains a byte load whose offset the interval domain cannot
bound, so alivio rejects it — exactly as the kernel verifier does:

```
[Verifier] FAILURE: Stack out of bounds at pc 9: offset 0, size 1
Section 'tracepoint/syscalls/sys_enter_execve'... FAIL
```

The load is nonetheless safe; establishing that just takes more than
interval arithmetic. Point alivio at a BCF-patched cvc5 and it discharges
the rejection with a machine-checkable proof:

```bash
ALIVIO_CVC5=/path/to/bcf-cvc5 \
  ./target/release/alivio --bcf --kernel-mode verify bcf-tests/shift_constraint.bpf.o
```

```
[INFO] [bcf] refined stack-OOB at base=R2 off=0 size=1: cvc5 proof 11688 bytes (hash 53bad2296570f686)
[INFO] [bcf] wrote bundle: bcf-tests/shift_constraint.bpf.o.bcf-bundle (1 entries, 11920 bytes)
[Verifier] Success! Verified 13 instructions (pruned 1 states).
```

(Proof and bundle sizes depend on your cvc5 build; the hash does not.)

That `.bcf-bundle` is what a BCF-patched kernel consumes at load time to
accept the program. Getting the solver, the patched kernel, and the VM
loader in place is the subject of **[SETUP.md](SETUP.md)**; more sample
objects are in [`bcf-tests/`](bcf-tests).

*Formerly named `zovia` (after the zone domain it started with). The binary,
the crate, and every `ALIVIO_*` environment variable use the new name; there
are no compatibility aliases for the old ones.*

## Features

* **Kernel Verifier Mirror (`--kernel-mode`):** LIFO-DFS exploration,
  `is_state_visited`-style pruning, and precision backtracking matching the
  kernel verifier. This is the mode used for all BCF work.
* **BCF Proof Bundles (`--bcf`):** Per-rejection SMT goals proven with a
  BCF-patched cvc5; proofs are packed into a `.bcf-bundle` sidecar the
  patched kernel consumes at load time.
* **Abstract Interpretation (Zone Domain):** Difference Bound Matrices (DBM)
  track relational constraints (e.g., `r1 < r2 + 10`) and value ranges.
* **Tri-state Numbers (Tnum):** Bitwise knowledge (known-0 / known-1 /
  unknown bits) for precise bitwise-operation analysis.
* **Context Validation:** Strict access rules per BPF program type
  (`sk_buff`, `xdp_md`, `bpf_sock_addr`, ...), table-driven under
  `common/ctx_model/`.
* **Map Safety:** Map lookups and value dereferences, map-in-map, global
  data (`.rodata`).
* **CO-RE Relocations:** Parses `.BTF.ext` records and applies them against
  a target kernel BTF blob (`--target-btf`); resolves `__ksym` externs.
* **dynptr, kptr, RCU, Iterators, Struct Ops, Arena:** `bpf_dynptr_*`
  semantics, kernel-pointer arithmetic and `bpf_kptr_xchg`, RCU read-lock
  nesting, `bpf_iter__<subtype>` entry synthesis, struct_ops/callback typing
  from BTF signatures, `__arg_arena` parameters.
* **Loop Handling:** Back-edge detection, widening, and (in zone mode)
  bounded-loop pattern detection for faster convergence.
* **Selftest & Benchmarking Harness:** Built-in runners for the upstream
  C selftest suite, the legacy JSON corpus, and JSONL bulk corpus emission
  that the Python harnesses in `scripts/` build on.

## BCF Proof Bundles

BCF ("BPF Certificate Format") turns verifier rejections into provable
side-conditions. The workflow:

```
alivio --bcf --kernel-mode verify prog.o        # writes prog.o.bcf-bundle
```

1. **Symbolic tracking.** With `--bcf`, the verifier maintains a parallel
   symbolic DAG per path alongside the abstract interpretation
   (`refinement/symbolic.rs`).
2. **Goal construction.** At a safety-check rejection site, a refinement
   goal is built from the path condition and the failed check — map/packet
   bounds (`refine_map.rs`), stack bounds (`refine_stack.rs`), or
   path-unreachability (`refine_unreachable.rs`).
3. **Solving.** The goal is lowered to SMT-LIB v2 (`smtlib.rs`) and handed
   to a BCF-patched **cvc5** (`solver.rs`), which emits a binary BCF proof
   on `unsat`. Point at your binary with the `ALIVIO_CVC5` environment
   variable.
4. **Bundle emission.** Proven (goal, proof) pairs are packed into a
   `.bcf-bundle` sidecar next to the input (`bundle.rs`; wire format frozen
   in `c-ref/bcf_bundle.h`).
5. **Kernel discharge.** At load time the BCF-patched kernel, on hitting the
   same rejection, computes the canonical hash of its own goal expression
   and looks it up in the supplied bundle (`canonical_hash.rs` mirrors the
   kernel's α-equivalent structural fingerprint; spec in
   `docs/userspace-bcf/canonical-hash-spec.md`). On a hash hit it re-checks
   the proof with its in-kernel checker and, only if the proof validates,
   discharges the rejection.

**FA=0 is the hard soundness floor:** only cvc5-proven goals are ever
emitted, and the kernel independently re-checks every proof — a bundle can
never make the kernel accept a program the proof doesn't justify.

### Design: BCF as an encapsulated, off-able module

The codebase is modularized so that BCF is strictly additive:

* **Core verification** lives in `analysis/` — abstract state in
  `machine/`, CFG/liveness/pruning/precision in `flow/`, per-instruction
  transfer functions in `transfer/`, and the LIFO-DFS driver in
  `worklist.rs`.
* **All BCF machinery** lives in `refinement/` — symbolic state, the goal
  builders (`refine_map`, `refine_stack`, `refine_unreachable`), SMT-LIB
  lowering + cvc5 dispatch (`smtlib`, `solver`), bundle serialization
  (`bundle`), the kernel-hash mirror (`canonical_hash`), and the emission
  drivers that run during verification in
  `refinement/emit/{record,replay,unreachable,map}.rs`.
* Core code touches BCF only through one-line hooks gated on
  `bcf_enabled`. With BCF off (the default), none of it runs — zero
  behavior change for non-BCF verification.

## Installation

**[SETUP.md](SETUP.md) is the full guide.** It is organized in three tiers;
pick the lowest one that covers what you need, since only tier 3 requires
Linux and a patched kernel.

| Tier | What you can do | What it needs |
|---|---|---|
| **1 — Verifier** | Verify `.o` / `.c` / `.json` in zone or kernel mode, PCC, selftests, corpus sweeps | Rust (+ clang for `.c`) |
| **2 — Proofs** | …plus generate `.bcf-bundle` proof bundles | + BCF-patched cvc5 (`ALIVIO_CVC5`) |
| **3 — Kernel discharge** | …plus watch a patched kernel *accept* those programs | + patched kernel, VM, loaders (Linux + KVM) |

Tier 1 is just:

```bash
cargo build --release
```

Tiers 1 and 2 run on Linux and macOS. Tier 3 is roughly an hour on a fresh
Linux box — its kernel side lives in [`linux-deltas/`](linux-deltas): the
four BCF patches (canonical hash, bundle UAPI, bundle parser, per-site
discharge hook), the `test_loader` / `ll2_loader` sources SETUP.md builds
inside the VM, and a target BTF blob for `--target-btf`.

## Architecture Overview

### Loading and Parsing Pipeline

```
ELF File (.o)
    │
    ├─► ELF Parsing (goblin)
    │   ├── Extract section headers and names
    │   ├── Load BPF maps from .maps section
    │   ├── Parse BTF (BPF Type Format) if present
    │   ├── Apply CO-RE relocations (--target-btf)
    │   └── Process relocations for map references
    │
    ├─► Raw Instruction Extraction
    │   ├── Locate code sections (e.g., "tc", "xdp", "kprobe/...")
    │   ├── Extract 8-byte BPF instructions
    │   └── Identify function boundaries via symbols
    │
    ├─► AST Lowering (bpf_to_ast)
    │   ├── Decode opcodes into typed instructions (incl. LD_IMM64)
    │   ├── Resolve branch targets
    │   └── Validate instruction encoding
    │
    └─► Control Flow Graph Construction
        ├── Identify basic blocks
        ├── Build predecessor/successor edges
        ├── Detect loops (back-edges) and SCCs
        └── Compute liveness information
```

**Key Modules:**
- `parsing/elf/` - ELF file handling: sections, symbols, relocations, struct_ops
- `parsing/bpf_insn.rs` - Raw BPF instruction representation
- `parsing/bpf_to_ast.rs` - Instruction decoding to typed AST
- `parsing/btf/` - BPF Type Format: parsing, `.BTF.ext`/CO-RE, map defs
- `analysis/flow/cfg.rs` - Control flow graph construction
- `analysis/flow/liveness.rs` - Register liveness analysis
- `analysis/worklist.rs` - The exploration driver (kernel `do_check` mirror)

### Abstract Domain

The verifier tracks program state using complementary abstract domains:

**1. Numeric Domain (selectable via flags)**

*Zone Domain (default, `--zone-mode`):*
- Difference Bound Matrices (DBM) represent constraints `xi - xj <= c`
- Tracks relational bounds between registers (e.g., `r1 <= r2 + 10`)
- Floyd-Warshall closure for constraint propagation
- More precise than the kernel, especially for packet bounds checking

*Interval Domain (`--kernel-mode`):*
- Per-register bounds only (signed/unsigned 32/64-bit min/max)
- Matches the kernel verifier's numeric analysis
- The mode used for kernel-faithful mirroring and all BCF work

**2. Tri-state Numbers (Tnum)** — each bit classified as known-0, known-1,
or unknown; precise bitwise-op analysis, used in both modes.

### Kernel Compatibility Mode

`--kernel-mode` makes alivio mirror the kernel verifier's exploration, not
just its numeric domain:

- **Interval domain** instead of DBM (bounded-loop detection off; loop
  back-edges allowed, matching the privileged/`bpf_capable` kernel path).
- **LIFO-DFS worklist** matching `do_check`'s push/pop order.
- **`is_state_visited` pruning:** states are cached at prune points and new
  arrivals are pruned when an old state subsumes them, with the kernel's
  state-cache placement and `add_new_state` heuristic.
- **Precision backtracking** (`analysis/flow/precision.rs`): registers and
  stack slots are marked precise by walking the instruction history
  backwards, frame-indexed like the kernel's `bt->reg_masks[frame]`, so
  imprecise-scalar pruning matches the kernel's.

This is the mode under which the 360/360 BCF result was produced: same
exploration order, same prune verdicts, same rejection sites — so the goals
alivio proves are the goals the kernel actually needs discharged.

### Pruning Strategy

#### 1. State Subsumption
At prune points, the verifier checks whether the current state is *subsumed*
by a previously cached state (`analysis/flow/pruning/subsumption.rs`):

- **Type Subsumption:** register types must be compatible
- **Range/DBM Subsumption:** old bounds at least as permissive as current
- **Tnum Subsumption:** old unknown bits a superset of current's
- **Stack Subsumption:** slot types compatible across all frames
- **Precision-aware:** in kernel mode, imprecise scalars are skipped
  exactly as the kernel's `regsafe` does

If an old state subsumes the current one, the current path is pruned;
otherwise exploration continues and the state is cached for future compares.

#### 2. Loop Handling
- Back-edges detected during CFG construction; SCC analysis
  (`analysis/flow/scc.rs`) scopes loop membership.
- Zone mode offers widening (`--use-widening`) and bounded-loop pattern
  detection (`if (r != K) goto loop_head` → constrain `r < K`) for faster
  convergence.
- Kernel mode instead relies on kernel-faithful state equivalence plus
  precision backtracking to converge loops, like the real verifier.

#### 3. Liveness-Based Pruning
Only live registers (those that may be read before being overwritten) count
in subsumption checks, mirroring the kernel's liveness marks.

## Usage

The CLI is a small Rust binary (`alivio`, three user-facing verbs plus a
hidden `dev` harness) with Python tools under `scripts/` for corpus
benchmarking and baseline diffing. Build with `cargo build --release`, then
invoke `./target/release/alivio` (or `cargo run --release --`).

### Top-level commands

```
alivio elf    <path> [...]      Inspect ELF / BTF contents (no verification)
alivio verify <path> [...]      Verify an eBPF program (auto-detects .o, .c, .json)
alivio pcc    <gen|check|cycle> Proof-Carrying Code certificate workflows
alivio dev    <subcommand>      Internal corpus / baseline / selftest harness
```

`alivio --help` and `alivio <verb> --help` print the full clap-generated flag
table — the canonical reference. Highlights below.

#### `elf <path>`

| Flag | Effect |
| --- | --- |
| *(none)* | List sections, programs, and maps |
| `--section <S>` | Analyze a single section |
| `--func <F>` | Analyze the section containing a given function |
| `--all` | Analyze every code section in the file |
| `--struct-ops <S>` | Diagnostic: dump the struct\_ops methods of struct `S` |
| `--btf-func <F>` | Diagnostic: print BTF parameter list of FUNC `F` |
| `--bindings` | Diagnostic: dump struct\_ops bindings from `.struct_ops` sections |

#### `verify <path>`

Auto-detects input by extension:
* `.o` → ELF (use `--section S`, `--func F`, or default to whole file)
* `.c` → upstream selftest source, compiled via clang (use `--defines D1,D2,…`)
* `.json` → legacy test catalogue. Bare `verify foo.json` lists tests; pick
  one with `--test "<name>"`. (Bulk runs live under `dev legacy-selftest`.)

`--kind elf|c|json` forces the input kind when the extension is ambiguous.

With `--bcf`, ELF verification writes a `<input>.bcf-bundle` sidecar
(cleared and rebuilt on each run) containing every proven refinement for
the object's sections.

#### `pcc <gen|check|cycle>`

```
alivio pcc gen   <json> --test <name> [--out <cert>]    # zone-mode generation
alivio pcc check <json> --test <name> --cert <path>     # interval-mode verify
alivio pcc cycle <json> --test <name> [--out <cert>]    # gen + check in one
```

#### `dev <subcommand>`

Internal harness commands; not part of the user-facing surface and subject
to change. `alivio dev --help` is the list. Three matter to outside
readers:

* `dev selftest-file` / `dev selftest-suite` — compile and verify upstream
  C selftests (one file, or a directory). Exits non-zero if a file fails to
  build, as distinct from failing to verify.
* `dev selftest-baseline-{write,check}-upstream` — sweep a kernel checkout
  to write the gold-standard baseline, then gate future changes against it.
* `dev verify-corpus` — JSONL emitter, one record per file/section. The
  single Rust entrypoint every Python harness in `scripts/` sits on.

### Configuration flags (global)

All flags are global and may appear before *or* after the subcommand. These
are the ones that change what you get; `alivio --help` lists the rest
(loop-entry strictness, private-stack model, widening, path tracing,
per-PC state caps, diagnostics).

| Flag | Effect |
| --- | --- |
| `--kernel-mode` | Mirror the kernel verifier: interval domain + kernel exploration order. Required for BCF work |
| `--zone-mode` | Zone domain (default, more precise than the kernel) |
| `--bcf` | Enable BCF symbolic tracking + proof emission; writes `.bcf-bundle` sidecar |
| `--target-btf <PATH>` | Kernel BTF blob for applying CO-RE relocations |
| `--max-insn <N>` | Step budget (default 1,000,000; also raises the BCF budget) |
| `--bcf-max-insn <N>` | BCF-mode complexity budget (default 4,000,000; base mode keeps `--max-insn`) |
| `--map-override <name:size>` | Override a map's value size, repeatable |
| `-q` / `-v` / `--very-verbose` | Verbosity: errors only / trace / full debug |

### Debug instrumentation (environment variables)

A small, curated set of **print-only** diagnostics — by design no
environment variable changes verification behavior:

| Variable | Prints |
|---|---|
| `ALIVIO_DUMP_AST=1` | The lowered instruction stream (the tool's "objdump") |
| `ALIVIO_TRACE_PC_RANGE=LO:HI` | Per-visit forensics inside a PC window: arrivals, subsumption verdicts, cache events, worklist push/pop, branch counts |
| `ALIVIO_DUMP_SUBSUM_MISS=1` | Per-register/slot/type dimensions of every subsumption miss ("why didn't it prune") |
| `ALIVIO_BCF_CENSUS=1` | One line per BCF goal formed (class, pc, hash, dup) |
| `ALIVIO_BCF_DUMP_HASH_BYTES=1` | Canonical goal bytes (for external diffing) |
| `ALIVIO_BCF_DUMP_PATH_COND_PCS=1` | Recorded path conditions with their emit PCs |
| `ALIVIO_DUMP_DISCHARGE=1` | Per-reject discharge summary + children_unsafe markings |
| `ALIVIO_BCF_REPLAY_DEBUG=1` | Base→reject replay progress and failures |
| `ALIVIO_BCF_TRACK_DEBUG_PC=<pc>` | Backward demand-walk trace anchored at a reject PC |
| `ALIVIO_DUMP_REGMASK=1` | The reject's refine target-register mask |
| `ALIVIO_DBG_MAT=1` | Every symbolic VAR materialization (reg, pc, bounds) |
| `ALIVIO_BCF_DUMP_SMT=<dir>` / `ALIVIO_BCF_DUMP_PROOF=<prefix>` | SMT-LIB queries / raw proof blobs |
| `ALIVIO_SOLVER_STATS=1` | cvc5 invocation counts and timing |
| `ALIVIO_BCF_CHECKER=<path>` | Cross-check each proof with the external bcf-checker |

Operational (behavior-relevant) env vars: `ALIVIO_CVC5` (solver binary
path), `ALIVIO_BUNDLE_KEEP=1` (skip clearing a stale bundle sidecar for
cross-run accumulation), `ALIVIO_BCF_EAGER_FLUSH=<path>` (flush the bundle
after every push, for runs that may be killed).

## Examples

These run against objects that ship in [`bcf-tests/`](bcf-tests), so they
work in a fresh clone.

**1. Inspect an object file** — sections, programs, maps, no verification:
```bash
alivio elf bcf-tests/ksnoop.bpf.o
```
```
--- SECTIONS ---
  [4] kprobe/foo (Kind: Kprobe)
  [6] kretprobe/foo (Kind: Kprobe)

--- BPF PROGRAMS ---
  [0] ksnoop (550 insns) [Section: .text, Kind: Unknown]
  ...
--- BPF MAPS ---
  [1] ksnoop_func_map (k:8, v:16296)
```

**2. Verify one section / one function / the whole file** — this one passes
outright, no proof needed:
```bash
alivio verify bcf-tests/system_monitor.bpf.o --section kprobe/security_bprm_check
alivio verify bcf-tests/system_monitor.bpf.o --func kprobe__security_bprm_check
alivio verify bcf-tests/system_monitor.bpf.o              # all sections → PASS
```

Most of the other objects in `bcf-tests/` are the opposite by design: they
are safe programs the interval domain can't justify, so plain `verify`
rejects them and `--bcf` is what closes the gap.

**3. Build a BCF proof bundle for an object:**
```bash
ALIVIO_CVC5=/path/to/bcf-cvc5 \
  alivio --bcf --kernel-mode verify bcf-tests/stack_ptr_varoff.bpf.o
# → bcf-tests/stack_ptr_varoff.bpf.o.bcf-bundle, ready for the BCF-patched loader
```

`bcf-tests/ksnoop.bpf.o.bcf-bundle` is a checked-in bundle for the largest
of these objects, if you want to inspect the wire format
(`c-ref/bcf_bundle.h`) without running a solver.

**4. Run a single legacy JSON test** — list the catalogue, then pick one:
```bash
alivio dev legacy-selftest list selftests/legacy/verifier/calls.json
alivio verify selftests/legacy/verifier/calls.json --test "calls: basic sanity"
```

**5. Verify a C selftest** (compiles with clang against vendored headers —
no kernel checkout needed):
```bash
alivio dev selftest-file selftests/progs/bpf_dctcp.c
```

**6. Run upstream selftests in kernel-compatible mode** — needs a v6.15
kernel tree; `vendor/` is gitignored, see [SETUP.md §1.4](SETUP.md):
```bash
alivio --kernel-mode dev selftest-suite vendor/linux/tools/testing/selftests/bpf/progs
```

**7. End-to-end BCF bundle bench on a corpus** (tier 3; needs the VM):
```bash
scripts/bench_e2e.py --list /tmp/calico_repr_list.txt --jobs 8 \
    --out /tmp/bench.tsv --kernel-test
```

## Troubleshooting

* **`FAIL: Complexity limit of 1000000 exceeded`** — too many execution
  paths. Raise `--max-insn <N>` (BCF runs already default to a 4M budget);
  in zone mode `--use-widening` forces loop convergence and `--skip-dbm`
  skips relational analysis (faster, less precise).
* **`FAIL: Stack out of bounds at pc 12: offset -128, size 8`** — access
  outside the stack frame or beyond a map value boundary; bound-check the
  offset before the access.
* **`FAIL: Unsafe generic load at pc 45: base R0, offset 0`** —
  dereferencing a possibly-NULL or non-memory pointer; null-check after map
  lookups / pointer-returning helpers.
* **`FAIL: Relocation info missing at pc 5`** — the ELF lacks relocation
  data for maps or globals; compile with `-target bpf` and a recent
  Clang/LLVM. For CO-RE-relocated objects, pass `--target-btf`.
* **`cvc5 binary not found at ...`** (`--bcf`) — set `ALIVIO_CVC5` to a
  BCF-patched cvc5 binary (one built with `--proof-format=bcf` support).
